Why target size is the useful control

It connects the compression task to the real-world requirement instead of making you guess which quality level will be small enough.

1

Start with the best source image you have. Recompressing an already degraded copy gives you less useful material to work with.

2

Use the KB or MB limit given by the form, portal, application or website.

3

Judge both size and appearance. A successful compression is one that fits the destination and remains fit for purpose.

Website assets

When an upload system has a hard per-image ceiling.

Exact target does not mean identical input

A simple graphic and a detailed photograph can need very different amounts of data. Dimensions, colors, texture, transparency and format all affect the achievable result. That is why Shrink treats the requested number as a target to work toward, then leaves the final quality check with you.

Exact image size questions

Can every image be made exactly 100KB?

No. Some images cannot hit a particular target while remaining useful. The source content and chosen format matter.

Can I choose MB instead of KB?

Yes. Shrink's target-size interface supports KB and MB values.

Does the original image get uploaded?

The normal image compression step runs locally in the browser.
